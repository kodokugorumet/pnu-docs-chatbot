## S1. 평가는 서비스 경로(/chat) 기준으로 측정한다

`scripts/evaluate_service_answers.py`는 벤치마크 트랙처럼 검색·생성을
직접 조립하지 않고, **실행 중인 search_api의 POST /chat을 호출**해서
답변을 수집한다. 역할 매핑, 프롬프트 조립, 공급자 폴백 체인, 근거 검증까지
사용자가 실제로 받는 경로 전체가 측정 대상이 되게 하기 위함이다. 서비스
쪽 구현이 바뀌면 평가도 자동으로 그 구현을 측정한다.

## S2. judge는 벤치마크 트랙과 조건을 통일한다

- `evaluate_grant_generation.call_gemini_judge`를 import해서 사용
  (`judge_rival_answers.py`와 같은 검증된 재사용 지점). 전송·temperature
  0.0·0~2 척도 동일, 프롬프트만 서비스 일반형(`SERVICE_JUDGE_PROMPT` —
  "연구비 규정 상담" → "대학 행정 안내", 척도 문안은 동일).
- 이를 위해 `call_gemini_judge`에 `prompt_template` 기본 인자를 추가했다.
  기본값이 기존 `JUDGE_PROMPT`이므로 연구비 트랙 호출부는 바이트 동일.
- **A/B 실행 시 `GEMINI_MODEL=gemini-3.1-flash-lite` 인라인 고정** 규칙
  승계 (D48-c 사고 재발 방지).
- n=3 반복, 파일 명명 `-run1/-run2/-run3` 규약 승계. 노이즈 밴드는
  연구비 트랙의 ±0.04(D43)를 잠정 승계하되, 서비스 트랙 자체의 반복
  측정이 쌓이면 재추정한다.

## S3. 평가셋은 앵커 문서 + 기계 검증으로 구축한다

기준답안이 없는 트랙이므로 LLM이 문항 초안을 만들되, 신뢰는 기계 검사로
보증한다:

- 문항마다 앵커 문서(현행·실질 정보 문서)를 정하고, 기준답안(reference)은
  앵커 문서 본문에 실재하는 사실만 담는다.
- 각 문항은 `evidence[{chunk_id, quote}]`를 포함한다. quote는 해당 청크
  본문의 **연속 부분 문자열(20자 이상)**이어야 한다.
- `scripts/validate_service_eval.py`가 스키마, evidence 부분 문자열,
  기대 출처와 앵커 문서의 정합(제목 포함·호스트 일치)을 검사한다.
  이 검사를 통과하지 못한 문항은 평가셋에 들어갈 수 없다.
- 평가셋: `config/pnu-service-answer-eval.jsonl`. 문항 id는
  `svc_<영역>_<번호>`, 역할 변형 문항은 `_r<역할>` 접미.
- 역할 변형 문항(role 필드 지정)은 역할 기반 응답(요구 #2)이 사실 품질을
  훼손하지 않는지를 같은 기준답안으로 측정한다.

## S4. 집계는 스크립트로 재현한다

`scripts/summarize_generation_runs.py`: n런의 문항별 평균 → 전체 평균,
`--exclude`(확보50 재현), `--runs-b`로 A/B 문항별 승/무/패와 Δ 산출.
연구비·서비스 트랙 산출물 모두에서 동작한다 (id + judge.score만 요구).
20260811-gen-anchor14 3런으로 동작 검증 완료.

## 프로토콜 (서비스 트랙 정본 실행 순서)

```bash
# 1) 서비스 기동 (평가 대상 구성 그대로)
python3 scripts/search_api.py --port 8000 \
  --index processed/index/pnu-20260725-curated-cascade-v5-allow-suspect.sqlite

# 2) 평가셋 무결성 검증 (문항 변경 시마다)
python3 scripts/validate_service_eval.py

# 3) 답변 수집 + 채점 (n=3이면 --out의 -runN만 바꿔 3회)
GEMINI_MODEL=gemini-3.1-flash-lite GEMINI_FALLBACK_MODELS=gemini-3.1-flash-lite \
  python3 scripts/evaluate_service_answers.py \
  --api-base http://127.0.0.1:8000 \
  --out processed/eval/20260831-svc-gen-baseline-run1.jsonl --sleep 4

# 4) 집계 / A/B
python3 scripts/summarize_generation_runs.py \
  --runs processed/eval/20260831-svc-gen-baseline-run*.jsonl
```

주의: 3)은 서비스의 생성 호출(Gemini)과 judge 호출이 함께 나가므로
문항당 API 2회다. RPD가 벤치마크 트랙과 공유되니 A/B가 예정된 날에는
실행 전에 잔여 쿼터를 고려할 것.
